# FinFlow — validasi tour onboarding, wizard pengaturan awal dan preferensi tampilan

## Ringkasan 3 November 2026

Tour onboarding Ollo empat slide dan wizard pengaturan awal enam langkah sudah ditulis, dihubungkan ke alur pertama kali, lalu diperiksa pada HP Xiaomi pengguna (bukan emulator). Build debug, APK pengujian, unit test Kotlin dan 20 uji instrumentasi berhasil. Dokumen ini mencatat perubahan yang divalidasi, hasil pemeriksaan yang benar-benar dijalankan, cara membuka mode pratinjau QA, batas yang belum diuji, dan lokasi bukti.

Pemeriksaan dilakukan 3 November 2026 sekitar pukul 09.57–10.15 WIB. Tangkapan layar perangkat berukuran 1220×2712 px. Pemeriksaan ronde 2 pada sore hari yang sama (sekitar 14.08–14.16 WIB, Asia/Jakarta) menambah validasi nama wajib, perombakan dialog mata uang, dan uji end-to-end nyata mode lokal di HP; ringkasannya ada di bagian berikut.

## Pembaruan ronde 2 — validasi & error handling pengaturan awal

Ronde 2 dijalankan pada 3 November 2026 sore, sekitar 14.08–14.16 WIB (Asia/Jakarta), pada HP Xiaomi pengguna yang sama, bukan emulator. Fokusnya dua temuan QA pada wizard pengaturan awal dan uji end-to-end nyata mode lokal pada data bersih.

### Perubahan yang divalidasi pada ronde 2

- Validasi nama lengkap wajib ala Ollo pada wizard pengaturan awal: menekan "Lanjut" dengan nama kosong tetap berada di langkah welcome, field bertanda merah dan menampilkan teks error inline "Nama lengkap wajib diisi." (ID) atau "Full name is required." (EN) dengan testTag `setup-name-error`; error hilang saat pengguna mengetik. `finish()` memiliki pertahanan ganda agar tidak pernah memanggil `onComplete` dengan nama kosong. File: `OlloSetup.kt`, `OlloSetupStrings.kt`.
- Dialog "Lihat Semua" mata uang dirombak: `AlertDialog` ungu bawaan Material3 dihapus dan diganti `OlloCurrencyDialog` (`OlloCurrencyPicker.kt`) berupa sheet putih netral yang menempel di bawah, pencarian case-insensitive (kode dan nama), 45 mata uang dengan simbol+nama+kode, baris terpilih berbingkai hitam, empty state, dan tombol tutup. `EntryTheme` di `OnboardingScreen.kt` diubah menjadi `lightColorScheme` netral penuh sehingga warna ungu bawaan (#ECE6F0, #E8DEF8, #FFD8E4) tidak bocor ke dialog/alert/dropdown mana pun di alur onboarding/auth.
- Perbaikan kecil mode pratinjau QA: extra intent `finflow_preview_first_run` kini berhenti di layar "Pratinjau pengaturan awal selesai" dengan tombol Tutup, tidak kembali masuk ke wizard nyata bila tidak ada akun (bug loop yang ditemukan saat QA).

## Pembaruan ronde 6 — verifikasi integrasi Firebase

Ronde 6 dijalankan pada 3 November 2026 sore, setelah ronde 5, untuk memastikan fungsi cloud (Auth, Firestore, Storage dan Cloud Functions) berjalan dengan aturan yang sama seperti produksi. Verifikasi memakai Firebase Emulator Suite dengan project demo `demo-finflow`, bukan data produksi.

### Lingkungan pengujian

- Firebase CLI 15.34.2; host Node v24.18.1. Emulator: auth 9098, firestore 8088, storage 9198, functions 5008, hub 4409 (`firebase/firebase.json`).
- Emulator dijalankan dari `kotlinApp/firebase` dengan perintah berikut:

```powershell
firebase emulators:start --only auth,firestore,storage,functions --project demo-finflow
```

- Java default di PATH rusak (proses keluar dengan kode 3221226505), sehingga emulator dijalankan dengan `JAVA_HOME` menunjuk ke JBR Android Studio (`C:\Program Files\Android\Android Studio\jbr`, OpenJDK 25.0.4).
- Functions emulator memerlukan Node 22 sedangkan host memakai Node 24. Solusinya `npm install node@22 --no-save` di `firebase/functions` (hanya menambah `node_modules`; `package.json` tidak berubah). Setelah itu functions `requestAccountDeletion`, `resetFinancialData` dan `deleteAccountData` termuat.
- HP Xiaomi dihubungkan ke emulator lewat `adb reverse tcp:9098 tcp:9098`, `adb reverse tcp:8088 tcp:8088`, `adb reverse tcp:9198 tcp:9198` dan `adb reverse tcp:5008 tcp:5008`. Setelah pengujian, emulator dihentikan dan aturan reverse dihapus.
- Log: `kotlinApp/firebase/firebase-debug.log`, `kotlinApp/firebase/firestore-debug.log`; log suite perangkat `kotlinApp/build/lead-full-suite-firebase.log`.

### Cara menjalankan pengujian rules, storage, dan functions

Dari `kotlinApp/firebase/tests`, setelah emulator siap, tiap berkas dijalankan terpisah karena rules test dan storage test sama-sama membersihkan Firestore sehingga dapat saling mengganggu bila paralel:

```powershell
node --test rules.test.mjs
node --test storage.test.mjs
node --test functions.test.mjs
node --test data-reset.test.mjs
```
