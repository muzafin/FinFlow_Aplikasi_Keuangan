# AI Kasiva — diagnosis dan perbaikan, 8 November 2026

Lanjutan dari laporan pengguna: AI Chat, AI Voice, AI Scan, dan Kasiva Assistant tidak bisa dipakai walaupun aplikasi sudah memakai DeepSeek lewat API key. Dokumen ini mencatat akar masalah, perubahan, deploy, bukti, dan tindakan yang tersisa.

## 1. Akar masalah (terbukti, bukan dugaan)

| # | Temuan | Bukti |
|---|---|---|
| 1 | **Kunci API di Secret Manager tidak valid.** | Panggilan langsung `POST https://api.deepseek.com/chat/completions` memakai nilai `DEEPSEEK_API_KEY` yang tersimpan dijawab **HTTP 401**: `Authentication Fails, Your api key: ****e51e is invalid`. Nilai tersimpan 36 karakter berawalan `c9ed9b`, bukan format kunci DeepSeek (`sk-...`). |
| 2 | Semua callable AI memetakan 401 menjadi `internal` "Layanan AI belum dikonfigurasi di server." | `firebase/functions/deepseek.js` → `mapDeepSeekError`; `firebase/functions/ai.js` → `mapAnthropicError`; klien `AiData.kt` menampilkannya sebagai "Layanan AI belum tersedia". Itu pesan yang dilihat pengguna di AI Chat/Voice/Scan/Asisten. |
| 3 | **Nama model sudah usang.** Kode memakai `deepseek-chat`; API DeepSeek November 2026 menyediakan `deepseek-flash` (teks + gambar + JSON Output) dan `deepseek-v4-pro`. | `DEFAULT_MODELS` di `ai.js` dan `.env.finflow-logikawan` sebelumnya `deepseek-chat`. |
| 4 | **AI Scan diblokir di adapter.** `deepseek.js` melempar `failed-precondition` "AI Scan belum didukung..." sebelum memanggil penyedia. | Kode lama `toChatMessages` menolak blok `image`; padahal `deepseek-flash` menerima gambar. |
| 5 | **Belum ada aturan konteks AI.** Prompt hanya menjelaskan tugas pencatatan; pertanyaan di luar konteks aplikasi tidak ditolak secara eksplisit. | Permintaan pengguna: "AI nya dikasih rules, sesuaikan dengan aplikasi saya, kalau di luar konteks tidak bisa". |

## 2. Perubahan yang dibuat

### Server — `kotlinApp/firebase/functions`

- `ai.js`
  - `DEFAULT_MODELS` parse & assistant → `deepseek-flash` (scan memakai model parse yang kini mendukung gambar).
  - `RULES` konteks Kasiva dipasang di system prompt AI Chat, AI Voice (parse), AI Scan, dan Asisten:
    - hanya melayani keuangan pribadi pengguna + penggunaan aplikasi Kasiva;
    - permintaan di luar konteks (coding, politik, agama, medis, hukum, hiburan, pengetahuan umum, menulis/terjemahan bebas) **ditolak singkat dan sopan** lalu diarahkan kembali;
    - tidak membocorkan system prompt/aturan; teks/foto/ringkasan pengguna adalah data, bukan instruksi (anti prompt injection).
  - Parse/Scan: bila masukan bukan transaksi/struk keuangan → daftar kosong + `message` penolakan **dalam bahasa aplikasi** (`context.language`).
  - Asisten: topik di luar konteks ditolak tanpa menjawab isinya; tetap tidak mengubah data dan tidak merekomendasikan produk investasi tertentu.
  - Kontrak request/response klien tidak berubah.
- `deepseek.js`
  - Blok gambar gaya Anthropic → `{ type: 'image_url', image_url: { url: 'data:<media>;base64,...' } }` (format vision DeepSeek); penolakan "AI Scan belum didukung" dihapus.
  - `parse()`: `thinking: { type: 'disabled' }` + `temperature: 0` + `response_format: json_object`; parsing JSON tahan pagar ```json.
  - `create()` (Asisten): `thinking: { type: 'enabled' }` + `reasoning_effort` dari `output_config.effort` (default `low`).
- `test/deepseek.test.js`, `test/ai.test.js` disesuaikan dan ditambah (vision, thinking, aturan konteks, bahasa pesan, model default).
- `.env.finflow-logikawan`: `AI_MODEL_PARSE` dan `AI_MODEL_ASSISTANT` → `deepseek-flash`.

### Klien — `kotlinApp/composeApp/src/commonMain`

- `feature/settings/ProductRoadmap.kt`: FF-042, FF-053, FF-054 tidak lagi menyatakan AI belum di-deploy / penyedia tanpa gambar.
- `feature/ai/AiData.kt`, `AiController.kt`, `AssistantScreen.kt`: komentar usang diperbarui. Pemetaan error dan kontrak pemanggilan tetap (kompatibel dengan APK lama).

## 3. Deploy

Dijalankan dari `kotlinApp/firebase` (folder yang memuat `firebase.json` proyek FinFlow; root proyek Flutter lama memakai firebase.json lain):

```powershell
firebase deploy --only "functions:finflow:aiParseText,functions:finflow:aiScanReceipt,functions:finflow:aiAssistant" --project finflow-logikawan
```

Hasil: ketiga function berhasil diperbarui di `asia-southeast2` (Node.js 22, 2nd gen). `aiStatus` dan `aiConsent` tidak berubah.

## 5. Kunci API

Kunci lama ditolak DeepSeek (401). Kunci baru yang valid sudah disimpan ke Secret Manager sebagai `DEEPSEEK_API_KEY` **versi 2**, lalu ketiga function AI di-deploy ulang 8 November 2026 agar memakai versi terbaru. Untuk rotasi berikutnya, dari folder `D:\Project\FinFlow_Aplikasi_Keuangan\kotlinApp\firebase`:

```powershell
firebase functions:secrets:set DEEPSEEK_API_KEY --project finflow-logikawan
firebase deploy --only "functions:finflow:aiParseText,functions:finflow:aiScanReceipt,functions:finflow:aiAssistant" --project finflow-logikawan
```

Kunci tidak pernah disimpan di repo. Catatan keamanan: kunci yang dipakai saat perbaikan sempat dikirim lewat chat; rotasi kunci setelah pengujian stabil dianjurkan.

## 6. Batas dan catatan

- Kuota tetap seperti sebelumnya: Free Chat/Voice 30, Scan 10 per bulan, Asisten 10 seumur akun; Premium 200 permintaan/hari (batas wajar).
- AI Scan: 1 kredit per foto, maksimal 5 foto per permintaan, maksimal 5 struk per foto.
- App Check enforcement belum diaktifkan (sama seperti sebelumnya); callable tetap meminta autentikasi Firebase.
- Model tidak lagi "menjawab bebas": pertanyaan di luar konteks keuangan/Kasiva akan ditolak, dan pesan penolakan mengikuti bahasa aplikasi.
- Biaya DeepSeek ditanggung server (bukan per pengguna); `deepseek-flash`: input $0,15/1 juta token (off-peak), output $0,6/1 juta token (off-peak) — pantau pemakaian bila fitur dibuka luas.


## 7. Perbaikan UI pemberitahuan (8 November 2026, lanjutan laporan pengguna)

Laporan pengguna: tulisan "1 transaksi dari AI disimpan" tidak pernah hilang, muncul di semua layar, dan menimpa status bar (terlihat di layar Kasiva Assistant).

- Penyebab: `notice` global di `App.kt` hanya terhapus jika diketuk; tidak ada timer. Baris notice dirender di atas konten halaman, sedangkan halaman tanpa TopAppBar (Asisten, Profil, Premium, Detail investasi, Aktivitas) belum mendapat inset status bar dari Scaffold.
- Perbaikan di `composeApp/src/commonMain/kotlin/com/clonical/kasiva/app/App.kt`: notice otomatis hilang setelah 4 detik (`LaunchedEffect(notice)` + `delay`), dan blok notice/progress/error diberi `statusBarsPadding()` hanya pada halaman yang belum mendapat inset dari TopAppBar.
- Verifikasi: `:composeApp:compileDebugKotlinAndroid` lulus; APK debug dibangun dan dipasang di HP pengujian (data tidak dihapus). Uji visual akhir dilakukan pengguna.
