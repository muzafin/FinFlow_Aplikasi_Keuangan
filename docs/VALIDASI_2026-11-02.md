# FinFlow — nama aplikasi, akun Google, lanjutan Ollo dan Blaze

## Hasil pada 2 November 2026

- Build debug menggunakan nama **FinFlow**, mengikuti manifest utama. Override `FinFlow Kotlin` dihapus; nama project Gradle juga FinFlow. APK akhir sudah dipasang ulang ke Xiaomi `2311DRK48G` tanpa menghapus data aplikasi. Label APK diperiksa melalui `aapt2 dump badging`.
- Penyebab screenshot `PERMISSION_DENIED` terkonfirmasi melalui pembandingan rules aktif: cloud masih memakai schema sebelum tambahan metadata dompet/kategori Ollo. Pembuatan data awal akun baru ditolak, sehingga UI tidak sampai memuat Beranda. Ini berbeda dari akun kosong yang berhasil dimuat.
- Inisialisasi profil/dompet/kategori kini memakai schema inti, tetap atomik dan aman diulang. Nama Google dinormalisasi, maksimal 100 karakter. Dua akun terpisah berhasil dibuat lewat repository asli pada rules terbaru **dan** salinan rules cloud lama. Profil/dompet lama tidak ditimpa; akses lintas akun ditolak.
- Rules terbaru sudah diterbitkan ke `finflow-logikawan`. Akun produksi yang sebelumnya gagal berhasil membuka Beranda pada HP yang sama. Tidak menambahkan transaksi contoh ke akun produksi.
- Saat gagal memuat data, panel error mengikuti warna tema dan tombol **Keluar / Ganti Akun** tetap tersedia.
- Lanjutan Ollo yang sudah ditulis kini tervalidasi: preferensi tampilan, Beranda/Profil, detail dompet, statistik/filter/urutan, kalkulator/panel transaksi, kategori/subkategori/tag, pocket, bundle, transfer target tabungan, kartu/rekening serta backup/restore. Neon bergerak dan navigasi liquid glass dipertahankan. Ini bukan pernyataan kesetaraan seluruh layanan Ollo.

## Firebase yang aktif

- Blaze diverifikasi melalui Cloud Billing API, bukan hanya berdasarkan pilihan plan di UI.
- Bucket `finflow-logikawan.firebasestorage.app`, lokasi **ASIA-SOUTHEAST2 / Jakarta**, sudah dibuat dan ditautkan ke Firebase. Tidak ada anggota IAM publik.
- Storage hanya mengizinkan pemilik mengakses `users/{uid}/profile/avatar.jpg`, JPEG maksimal 2 MB. Foto dipilih melalui pemilih sistem, dinormalisasi dan dikompresi di perangkat; aplikasi tidak menyimpan tautan unduhan publik. Android dan implementasi Swift iOS disambungkan ke Profil → Manajemen Akun → **Ubah Foto Profil**.
- Cloud Functions generasi kedua **requestAccountDeletion** dan **deleteAccountData** berstatus **ACTIVE**, region `asia-southeast2`, runtime Node.js 22, minimum instance 0, maksimum 2 per fungsi. Artefak build memiliki cleanup policy satu hari.
- Hapus akun membutuhkan ketikan `HAPUS` dan autentikasi ulang Google/password. UID diambil dari token pemanggil, bukan dari input pengguna. Backend menulis penanda penghapusan yang langsung memblokir Firestore/Storage untuk token lama, kemudian membersihkan file, seluruh subkoleksi dan Firebase Auth. Worker aman diulang ketika terjadi kegagalan sementara; penanda dipertahankan setelah selesai.
- Endpoint produksi diperiksa tanpa autentikasi dan mengembalikan **401**. Tidak menghapus akun produksi untuk pengujian.
- Rules Firestore/Storage aktif diunduh ulang dan isinya cocok dengan berkas yang diuji. Ruleset Firestore: `743888f5-f089-4e61-8087-b833eacb9696`. Ruleset Storage: `8b266c30-0c56-4639-afcc-74a3c7e27ab4`.

Seluruh pengujian database/transaksi/penghapusan menggunakan project emulator **demo-finflow**, bukan database produksi. Log pengujian/deployment berada di `kotlinApp/build/backend-tools/`, log build di `kotlinApp/build/`, dan screenshot/XML di `kotlinApp/build/ollo-reference/`; semuanya diabaikan Git.

Menjalankan emulator: dari `kotlinApp/firebase`, gunakan Firebase CLI dengan `emulators:start --project demo-finflow --only auth,firestore,storage,functions`. Dari `firebase/tests`: `npm test`, `npm run test:storage`, dan `npm run test:functions`. Backend memiliki `npm test` tersendiri pada `firebase/functions`. Untuk device, gunakan APK aplikasi/test hasil build yang sama dan `adb reverse` port 8088/9098. Pada Windows ini, Java 21 dan Java agent loopback lokal diperlukan untuk Gradle/Emulator.

## Batas yang masih berlaku

- iOS belum dikompilasi/dijalankan di Mac/Xcode. Podspec sudah digenerasi ulang untuk Firebase Storage/Functions.
- Unggah foto nyata dan penghapusan akun nyata tidak dijalankan di produksi. Aturan unggahan, unggahan SDK dan alur penghapusan diuji di emulator; pemilih/kompresi foto native belum diuji dengan foto pengguna. Endpoint cloud hanya diperiksa penolakan tanpa login.
- Blaze menyediakan akses produk cloud, bukan otomatis menyediakan API bank, harga pasar/kurs, AI scan/voice/chat, APNs atau sertifikat rilis. Sinkronisasi bank tetap memerlukan penyedia/kredensial. AI/Premium Ollo yang sebelumnya ditunda belum dipindahkan. Fitur inti FinFlow tidak diberi paywall.
- Notifikasi anggaran masih lokal; belum ada pengirim FCM/APNs atau pelacakan/pencabutan sesi perangkat lain. App Check enforcement tetap belum diaktifkan sebelum klien attestation rilis siap.
- Penggunaan Storage/Functions mengikuti biaya Blaze. Retry worker dan penggunaan database/file tetap dapat menimbulkan biaya; `minInstances=0`, pembatasan instance/ukuran foto dan cleanup artefak membatasi penggunaan dasar, bukan hard spending cap.

Otomatisasi browser sempat dihentikan alat karena URL aktif tidak dapat dipastikan. Konfigurasi selanjutnya dilakukan melalui Firebase CLI/API resmi setelah pengguna melakukan login sendiri.

Satu pemeriksaan CLI sempat menampilkan token sesi pada output alat. Sesi CLI tersebut di-logout/dicabut sesudah verifikasi deployment; tidak ada token yang ditulis ke dokumentasi atau sumber aplikasi.
